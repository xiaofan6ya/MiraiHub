# 功能契约：缓存分析页（Cache Analytics）

**页面标识**: P14（TABS 中的「缓存分析」标签）  
**入口函数**: `loadCacheAnalytics(force, opts={days:7})`  
**路由**: `/console/cache-analytics` 或点击导航栏「缓存分析」

---

## 一、页面整体结构

```
┌─ 平台上下文切换器（侧栏顶部）
├─ 时间粒度切换（1天 / 7天 / 30天）
│
├─ 上半屏：缓存概览卡片矩阵
│  ├─ 缓存命中率卡片（大数字 + 趋势）
│  ├─ 缓存节省额度卡片（积分）
│  ├─ 缓存容量使用卡片（字节 / 百分比）
│  └─ 有效样本数卡片
│
├─ 中间屏：按模型分类表格（可排序、可筛选）
│  ├─ 列：模型名 / 命中率 / 缓存大小 / 命中次数 / 节省积分 / 趋势图
│  ├─ 点击行展开详情（该模型的平台分布）
│  └─ 合计行（汇总）
│
├─ 下半屏：按平台分类表格（可排序）
│  ├─ 列：平台名 / 命中率 / 缓存大小 / 命中 tokens / 总输入 tokens / 节省额度
│  └─ 合计行
│
├─ 缓存趋势图（时间维度）
│  ├─ X 轴：日期或时间
│  ├─ Y 轴：命中率（%）和节省积分（双轴）
│  └─ 交互：悬停显示日期、具体数值
│
└─ 底部：数据采集时间戳 + 刷新按钮
```

---

### 副接口

**获取缓存容量配置**（初始化时用）:
```http
GET /api/cache/config
```
返回 `{ "capacity_bytes": 1099511627776, "retention_days": 30, "enabled": true, ... }`

**获取模型列表**（筛选用，可选）:
```http
GET /api/models?include_cache_stats=true
```
返回 `[{ "id": "gpt-4", "name": "GPT-4", "supports_cache": true, ... }, ...]`

## 三、数据展示规范

### 3.1 数字格式化

#### 缩写格式（`ovNum()`）
- 用于大数字简化显示
- 规则：
  - ≥ 1 亿（1e8）：显示为 B（亿），2 位小数，如 `1.23B`
  - ≥ 1 万（1e4）：显示为 M（万），2 位小数，如 `12.34M`
  - ≥ 1 千（1e3）：显示为 K（千），1 位小数，如 `1.2K`
  - < 1 千：显示原数，四舍五入

#### 百分比格式（`ovPct()`）
- 用于命中率、使用率等百分比值
- 规则：乘以 100，保留 1-2 位小数，加 `%` 符号，如 `9.09%` 或 `15.0%`

#### 字节格式（`fmtBytes()`）
- 用于缓存大小显示
- 规则：
  - ≥ 1 GB：显示为 GB，1 位小数，如 `1.0 GB`
  - ≥ 1 MB：显示为 MB，1 位小数，如 `512.5 MB`
  - ≥ 1 KB：显示为 KB，1 位小数，如 `1.2 KB`
  - < 1 KB：显示为 B（字节），如 `512 B`

#### 金额格式（`ovCredit(sign)`）
- 用于节省积分显示
- 规则：千分位 + 固定 2 位小数，如 `1,234.56`
- 可选加正号：`+123.45`

#### 时间格式（`fmtTime(s, withSec)`）
- 输入：Unix 时间戳（秒）或 ISO 日期字符串
- 输出：本地时间（UTC+8），格式为 `YYYY-MM-DD HH:mm:ss` 或 `YYYY-MM-DD`

### 3.2 着色规则

#### 命中率着色
- 绿色（`ok`）：≥ 10%
- 黄色（`warn`）：5% ≤ < 10%
- 灰色（`neutral`）：< 5% 或无数据

#### 节省额度着色
- 绿色（`ok`）：≥ 100 积分
- 黄色（`warn`）：10 ≤ < 100 积分
- 灰色（`neutral`）：< 10 积分或无数据

#### 缓存容量使用率着色
- 绿色（`ok`）：< 50%
- 黄色（`warn`）：50% ≤ < 80%
- 红色（`danger`）：≥ 80%

#### 趋势着色（相对上一周期）
- 绿色向上（↑）：增长（命中率/节省提升）
- 红色向下（↓）：下降
- 灰色（→）：持平

## 四、交互与行为

### 4.1 页面加载

**首次进入**:
1. 显示加载状态（骨架屏）
2. 调用 `GET /api/stats/cache?days=7`（默认 7 天）
3. 渲染概览卡片、表格、趋势图
4. 记录加载完成时间

**时间粒度切换** (1天 ↔ 7天 ↔ 30天):
1. 更新 URL 参数或本地状态
2. 重新调用接口，`days` 参数更新
3. 平滑动画更新卡片数值和图表
4. 表格数据重排，趋势图重绘

**平台切换**（通过平台上下文事件 `wb-platform-change`）:
1. 触发 `loadCacheAnalytics(true, {days: currentDays})`
2. 重新加载所有数据并刷新显示
3. 表格和图表重新渲染

### 4.2 操作

#### 刷新按钮
- 位置：页面右上角或卡片右上角
- 行为：`loadCacheAnalytics(true)` 绕过缓存强制刷新
- 显示：最后刷新时间戳

#### 表格排序
- 点击列头进行排序
- 支持的列：命中率、缓存大小、节省积分、样本数
- 双击返回默认排序（按模型名或平台名字母序）

#### 表格筛选（可选）
- 筛选框：输入模型名或平台名进行模糊搜索
- 按命中率范围筛选：≥ 10% / 5-10% / < 5%
- 按节省积分范围筛选

#### 行展开（模型分类表）
- 点击某个模型行，展开该模型按平台的详细分布
- 展开内容包含：该模型各平台的命中率、缓存大小、样本数
- 收起时回到原状态

#### 趋势图交互
- 悬停显示详细数据提示（日期、命中率、节省积分）
- 点击日期可看到该天的详细数据（弹层或跳转）
- 双坐标轴：左侧 Y 轴为命中率（%），右侧 Y 轴为节省积分（￥）

#### 导出功能（可选）
- 导出按钮：支持导出为 CSV / Excel
- 包含内容：模型分类表、平台分类表、按日期的趋势数据
- 文件名格式：`cache-analytics_7days_2024-11-16.csv`

## 五、跨页联动

### 5.1 平台上下文
- 所有数据自动按 `X-Platform` 请求头过滤
- 切平台时 localStorage 同步更新
- CustomEvent `wb-platform-change` 由 platform-switch.js 发送，本页监听并重载

### 5.2 导航跳转
- 点击模型行的「查看详情」→ 跳转到「模型分析」页（如存在，附带模型 ID）
- 点击平台行的「查看详情」→ 跳转到「平台分析」页（如存在，附带平台代码）
- 从「概览」页（P1）的缓存卡片点击「查看详情」→ 跳转到本页

### 5.3 全局事件
- 当模型启用/禁用缓存功能时，本页自动刷新或提示用户重新加载
- 当缓存配置被管理员修改时（容量、保留期等），页面展示可能需要更新

## 六、边界情况与容错

### 6.1 数据缺失或异常

| 情况 | 处理 |
|------|------|
| 命中率为 null | 显示 `—` 或 `0.0%` |
| 缓存大小为 0 | 显示 `0 B` |
| 总输入 tokens 为 0 | 命中率显示 `—`，不计算百分比 |
| 节省积分为负 | 显示为 `0.00`（边界保护） |
| 模型列表为空 | 显示「暂无缓存数据」 |
| 平台列表为空 | 显示「暂无可用平台数据」 |
| 缓存容量不可用 | 使用率卡片显示 `—` |
| 趋势数据不足（< 2 天） | 不显示趋势图，显示文字提示 |
| 某日期数据缺失 | 在趋势图中用虚线或灰色表示缺失 |

### 6.2 加载态与错误

**加载中**:
- 显示骨架屏或灰色占位符
- 卡片内容淡出
- 表格显示「加载中…」

**请求失败**:
- 显示错误提示（Toast）：「数据加载失败，请检查网络连接」
- 保留上次成功的数据（若有）
- 提供「重试」按钮

**响应超时**（> 10 秒）:
- 显示降级视图（上次缓存数据或仅显示时间戳）
- 后台继续重试
- 收到响应后自动更新

**缓存功能未启用**:
- 显示信息提示：「当前平台暂未启用缓存功能」或「缓存功能仅部分模型支持」
- 所有卡片显示 `—` 或灰色

### 6.3 空状态

| 场景 | 显示 |
|------|------|
| 整个时间窗口无缓存数据 | 显示「当前时间范围内暂无缓存数据」，提示切换时间或平台 |
| 某模型无缓存数据 | 在表格该行显示「—」，不着色 |
| 某平台无缓存数据 | 在表格该行显示「—」，不着色 |
| 缓存已满 | 在容量卡片显示警告「缓存已满」，着色为红色 |
| 账户被禁用 | 顶部显示横幅「账户已禁用」，所有内容置灰 |

### 6.4 功能开关与平台差异

**缓存功能支持**:
- 若 `by_model` 为空但 `summary.hit_tokens > 0`，表示缓存数据还在聚合中，显示「数据更新中…」
- 某些模型不支持缓存：在列表中不显示或标记为「不支持」

**平台差异**:
- OpenAI、Deepseek 等不同平台的缓存机制差异，显示说明文案：「不同平台缓存机制不同，数据仅供参考」

**端差异**（PC vs 移动）:
- **PC**: 表格横向排列，所有列完整显示，趋势图宽屏显示
- **移动**: 表格竖向堆叠（卡片式布局），列部分隐藏或可滑动，趋势图响应式缩放

## 七、实现要点

1. **缓存策略**：
   - 页面数据缓存 1-2 分钟，用户点击刷新时 `force=true` 绕过缓存
   - 趋势数据（timeseries）缓存更长（5 分钟），因为粒度较粗

2. **性能优化**：
   - 大表格采用虚拟滚动（Virtual Scrolling），仅渲染可见行
   - 趋势图使用 canvas 或轻量级图表库（如 Chart.js）
   - 数据加载时，先显示概览卡片，再加载表格和图表（分步加载）

3. **数据更新**：
   - 轮询：每 5 分钟自动刷新一次数据（用户可配置关闭）
   - 实时：若平台支持 WebSocket 或 Server-Sent Events，可推送实时更新

4. **无障碍**：
   - 表格用 `<table>` 语义标签，列头用 `<th>`
   - 卡片用 `<article>` 或 `<section>` 语义标签，标题用 `<h2>` / `<h3>`
   - 趋势图提供 alt text 或表格形式的文字描述
   - 着色规则不单独依靠颜色，要有文字/图标补充（如 ↑ ↓ → 箭头）

5. **国际化**：
   - 所有文案（「命中率」「节省积分」等）需提取到 i18n 配置
   - 数字格式因语言而异（如中文千分位与英文不同）

6. **主题适应**：
   - 所有颜色变量用 CSS Custom Properties（`--c-ok` / `--c-warn` / `--c-danger` 等）
   - 支持亮/暗主题切换

7. **错误恢复**：
   - 若单个接口失败，尝试 3 次重试，每次间隔 2 秒
   - 若重试仍失败，显示"部分数据加载失败"，保留已加载的数据
