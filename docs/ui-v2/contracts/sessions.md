# 功能契约：会话管理页（Sessions Management）

**页面标识**: P3（TABS 第三个）  
**入口函数**: `sessionsReload(force=false)`  
**路由**: 应用启动时加载，或点击导航栏「会话」

---

## 一、页面整体结构

```
┌─ 页面标题（「会话管理」）
│
├─ 当前用户信息卡（顶部）
│  ├─ 用户名 / 账号 ID
│  ├─ 登录时间
│  ├─ IP 地址
│  └─ 客户端信息（User-Agent 或设备名）
│
├─ 活跃会话列表（主体）
│  ├─ 表格标题行：设备 / 登录时间 / 最后活动 / IP 地址 / 操作
│  ├─ 会话行（逐行显示）
│  │  ├─ 设备标识（从 User-Agent 解析出的设备类型或名称，如 Chrome/Safari/Mobile）
│  │  ├─ 登录时间（格式：YYYY-MM-DD HH:mm:ss）
│  │  ├─ 最后活动时间（距现在 N 分钟/小时/天前，或 HH:mm:ss）
│  │  ├─ IP 地址（带地理位置标签，可选：所在城市/运营商）
│  │  └─ 操作按钮
│  │     ├─ 「踢下线」(Revoke) - 仅当非当前会话时显示
│  │     ├─ 「拉黑」(Ban)
│  │     └─ 「当前设备」标记 - 对当前用户登录的会话
│  │
│  └─ 表格末尾：一键操作
│     └─ 「踢下其他设备」按钮（快速踢掉除当前设备外的所有会话）
│
├─ 拉黑设备列表（可折叠区域）
│  ├─ 区域标题：「已拉黑设备」
│  ├─ 拉黑记录行（逐行显示）
│  │  ├─ 设备标识
│  │  ├─ IP 地址
│  │  ├─ 拉黑时间（YYYY-MM-DD HH:mm:ss）
│  │  ├─ 拉黑原因（可选，如「多次异常登录」）
│  │  └─ 「解除拉黑」(Unban) 按钮
│  │
│  └─ 空状态：「暂无拉黑记录」
│
└─ 页面底部
   ├─ 数据更新时间戳
   └─ 「刷新」按钮
```

## 二、数据来源与接口

### 主接口

```http
GET /api/sessions
```

**返回字段**:

```json
{
  "current": {
    "sid": "sess_abc123def456",          // 当前会话 ID
    "device": "Chrome 120 (Windows)",    // 设备标识
    "ip": "203.0.113.42",                // IP 地址
    "login_at": 1700000000,              // 登录时间戳（Unix 秒）
    "last_at": 1700086400,               // 最后活动时间戳
    "user_agent": "Mozilla/5.0..."       // 原始 User-Agent
  },
  
  "sessions": [
    {
      "sid": "sess_xyz789uvw123",
      "device": "Safari (iPhone)",
      "ip": "192.0.2.100",
      "login_at": 1699999000,
      "last_at": 1700085000,
      "user_agent": "Mozilla/5.0 (iPhone; CPU iPhone OS 17_2...)",
      "state": "active"                  // "active" | "revoked"
    },
    {
      "sid": "sess_pqr456stu789",
      "device": "Firefox (macOS)",
      "ip": "198.51.100.50",
      "login_at": 1699900000,
      "last_at": 1699950000,
      "user_agent": "Mozilla/5.0 (Macintosh; Intel Mac OS X 10_15_7)...",
      "state": "revoked"                 // 已被踢下线，仅供显示历史记录
    }
  ],
  
  "bans": [
    {
      "ban_id": "ban_001",               // 拉黑记录 ID
      "device": "Unknown Device",        // 设备标识
      "ip": "203.0.113.99",              // 被拉黑的 IP
      "banned_at": 1699800000,           // 拉黑时间戳
      "reason": "多次异常登录尝试",      // 拉黑原因（可选）
      "expires_at": null                 // 拉黑过期时间（null 为永久）
    }
  ]
}
```

### 副接口

**踢下线**（撤销单个会话）:
```http
POST /api/sessions/{sid}/revoke
```

请求体：`{}`（可选）

响应：
```json
{
  "ok": true,
  "data": {
    "revoked": 1,
    "message": "会话已终止"
  }
}
```

**拉黑设备**（踢下线 + 记录 IP）:
```http
POST /api/sessions/{sid}/ban
```

请求体：
```json
{
  "reason": "多次异常登录尝试"  // 可选，拉黑原因
}
```

响应：
```json
{
  "ok": true,
  "data": {
    "ban_id": "ban_002",
    "ip": "203.0.113.42",
    "banned_at": 1700086401,
    "message": "设备已拉黑"
  }
}
```

**踢下其他所有设备**:
```http
POST /api/sessions/revoke-others
```

请求体：`{}`（可选）

响应：
```json
{
  "ok": true,
  "data": {
    "revoked": 3,
    "message": "已踢下线 3 台设备"
  }
}
```

**解除拉黑**:
```http
DELETE /api/sessions/ban/{ban_id}
```

响应：
```json
{
  "ok": true,
  "data": {
    "message": "拉黑已解除"
  }
}
```

## 三、数据展示规范

### 3.1 设备识别

从 User-Agent 解析并简化为可读的设备标识：

| User-Agent 匹配 | 显示文本示例 |
|---|---|
| Chrome + Windows | `Chrome 120 (Windows)` |
| Safari + iPhone | `Safari (iPhone)` |
| Firefox + Linux | `Firefox 121 (Linux)` |
| Edge + Windows | `Edge 120 (Windows)` |
| Unknown | `未知设备` 或 IP 地址 |

**实现方式**：
- 使用轻量级 UA 解析库（如 `ua-parser-js`）
- 若解析失败，显示 IP 地址作为备选标识

### 3.2 时间格式化

#### 登录时间 / 拉黑时间（`fmtTime(s, withSec)`）
- 格式：`YYYY-MM-DD HH:mm:ss`
- 输入：Unix 时间戳（秒）
- 时区：UTC+8（本地时区）

#### 最后活动时间（相对时间）
- 相对于当前时间的距离
- 规则：
  - ≤ 1 分钟：「刚刚」
  - < 1 小时：「N 分钟前」
  - < 1 天：「N 小时前」
  - ≥ 1 天：「N 天前」或「YYYY-MM-DD HH:mm」

### 3.3 IP 地址与地理定位

**显示规则**：
- 基础：显示 IP 地址本身（如 `203.0.113.42`）
- 增强（可选）：添加地理位置标签
  - 格式：`203.0.113.42 (北京, 中国联通)`
  - 获取方式：调用地理位置 API（可选）或在后端返回时附带

**特殊情况**：
- 本地 IP（`127.0.0.1`、`::1`、`192.168.x.x`）：标记为「本地」
- 代理 IP：标记为「代理」（如可检测）

### 3.4 状态标记

#### 当前会话标记
- 位置：会话行末尾或设备名后
- 样式：绿色徽章，文本「当前设备」
- 条件：`sid === current.sid`

#### 已撤销会话标记
- 位置：会话行末尾
- 样式：灰色文本或删除线
- 条件：`state === "revoked"`
- 显示原因：`已被踢下线，于 HH:mm 失效`

#### 拉黑过期标记
- 位置：拉黑记录行
- 样式：灰色徽章
- 条件：`expires_at !== null && expires_at < now`
- 显示文本：「已过期」

## 四、交互与行为

### 4.1 页面加载

**首次进入**:
1. 显示加载状态（骨架屏或空状态）
2. 调用 `GET /api/sessions`
3. 渲染当前用户卡片、会话表格、拉黑列表
4. 隐藏已撤销的会话（或灰显）

**手动刷新**:
1. 点击「刷新」按钮
2. 调用 `GET /api/sessions`
3. 更新表格内容（平滑过渡，不闪烁）

**自动刷新**（可选）:
- 每 30 秒自动刷新一次（后台轮询）
- 或提供切换选项让用户决定

### 4.2 操作交互

#### 踢下线（Revoke）

**触发条件**：
- 点击某行会话的「踢下线」按钮
- 该会话不能是当前用户的会话（按钮不显示）

**交互流程**：
1. 显示确认对话框
   - 标题：「确认踢下线」
   - 内容：「将踢下线设备『Safari (iPhone)』，该设备上的会话将立即失效。」
   - 按钮：「取消」「确认踢下线」

2. 用户确认后：
   - 发送 `POST /api/sessions/{sid}/revoke`
   - 显示加载状态（按钮禁用或转圈）
   - 请求成功：
     - 显示成功提示（Toast）：「已踢下线」
     - 该行变灰或隐藏，显示「已被踢下线，于 HH:mm 失效」
     - 1～2 秒后调用 `sessionsReload()` 刷新完整列表
   - 请求失败：
     - 显示错误提示（Toast）：「踢下线失败：{error_msg}」
     - 用户可重试

#### 拉黑（Ban）

**触发条件**：
- 点击某行会话的「拉黑」按钮

**交互流程**：
1. 显示确认对话框（可选带原因输入框）
   - 标题：「确认拉黑设备」
   - 内容：「将拉黑该设备的 IP 地址『203.0.113.42』，拉黑后该 IP 无法登录此账号。」
   - 可选：原因输入框（单行文本，占位符「多次异常登录尝试」）
   - 按钮：「取消」「确认拉黑」

2. 用户确认后：
   - 发送 `POST /api/sessions/{sid}/ban`（可选带 reason）
   - 显示加载状态
   - 请求成功：
     - 显示成功提示（Toast）：「设备已拉黑」
     - 该会话从活跃列表移到拉黑列表
     - 自动调用 `sessionsReload()` 刷新完整列表
   - 请求失败：
     - 显示错误提示（Toast）：「拉黑失败：{error_msg}」

#### 踢下其他设备（Revoke Others）

**触发条件**：
- 点击表格末尾的「踢下其他设备」按钮

**交互流程**：
1. 显示确认对话框
   - 标题：「确认踢下其他设备」
   - 内容：「将踢下线除当前设备外的所有会话（共 N 台设备），该操作不可撤销。」
   - 按钮：「取消」「我知道了，踢下线」

2. 用户确认后：
   - 发送 `POST /api/sessions/revoke-others`
   - 显示加载状态（按钮禁用或转圈）
   - 请求成功：
     - 显示成功提示（Toast）：「已踢下线 N 台设备」
     - 表格刷新，只保留当前设备（标记为「当前设备」）
     - 其他行变灰，显示「已被踢下线」
     - 1～2 秒后调用 `sessionsReload()` 刷新
   - 请求失败：
     - 显示错误提示（Toast）：「踢下线失败：{error_msg}」

#### 解除拉黑（Unban）

**触发条件**：
- 点击拉黑列表中某条记录的「解除拉黑」按钮

**交互流程**：
1. 显示确认对话框（简单版）
   - 标题：「确认解除拉黑」
   - 内容：「将解除对 IP『203.0.113.42』的拉黑限制，该 IP 可重新登录此账号。」
   - 按钮：「取消」「确认解除」

2. 用户确认后：
   - 发送 `DELETE /api/sessions/ban/{ban_id}`
   - 显示加载状态
   - 请求成功：
     - 显示成功提示（Toast）：「拉黑已解除」
     - 该记录从拉黑列表移除
     - 1～2 秒后调用 `sessionsReload()` 刷新
   - 请求失败：
     - 显示错误提示（Toast）：「解除拉黑失败：{error_msg}」

## 五、确认对话框规范

### 对话框通用样式

```
┌─────────────────────────────────────────┐
│ ✕                                       │
│                                         │
│ [Icon] 确认踢下线                       │
│                                         │

│ 备上的会话将立即失效。                 │

```

**样式规范**：
- 背景：模态层（半透明暗色）

  - 取消（灰色 Outline）
  - 确认（彩色 Solid，根据操作类型：绿色 revoke、红色 ban、黄色 revoke-others）
- 按钮间距：12px
- 按钮宽度：均等分配

## 六、边界情况与容错

### 6.1 数据缺失或异常

| 情况 | 处理 |
|------|------|
| 会话列表为空 | 显示「暂无其他设备」 |
| 拉黑列表为空 | 折叠/隐藏拉黑区域，或显示「暂无拉黑记录」 |
| User-Agent 解析失败 | 显示 IP 地址或「未知设备」 |
| 地理位置信息缺失 | 仅显示 IP，不显示地理标签 |
| 拉黑原因为空 | 显示「—」或不显示该字段 |
| 当前会话状态异常（state 不是 active）| 仍标记为「当前设备」，但添加警告 |

### 6.2 加载态与错误

**加载中**:
- 显示骨架屏（表格占位符）
- 或显示「加载中…」文案
- 刷新按钮禁用，显示转圈动画

**请求失败**:
- 显示错误提示（Toast）：「数据加载失败，请检查网络」
- 保留上次成功的数据
- 刷新按钮恢复可用，提供「重试」选项

**响应超时**（> 10 秒）:
- 显示降级视图（仅显示上次缓存数据）
- 后台继续重试
- 收到响应后自动更新

### 6.3 空状态

| 场景 | 显示 |
|------|------|
| 只有当前设备，无其他会话 | 表格显示一行「当前设备」，「踢下其他设备」按钮禁用或隐藏 |
| 该用户已被禁用 | 顶部显示横幅「账户已禁用，无法管理会话」，所有按钮禁用 |
| 新账户（首次登录） | 仅显示当前会话，拉黑列表为空 |
| 所有会话均已撤销（除当前） | 表格仅显示当前会话和灰显的历史记录 |

### 6.4 权限与校验

**当前用户操作限制**:
- 不能踢下自己的会话（「踢下线」按钮对当前会话隐藏）
- 不能拉黑自己的会话（「拉黑」按钮可见，但操作时后端应拒绝并返回错误）

**批量操作校验**:
- 「踢下其他设备」时，需排除当前会话
- 后端应校验，确保当前会话不被撤销

**IP 拉黑校验**:
- 拉黑当前会话所在 IP 时，前端可选提示「即将拉黑当前设备所在 IP」
- 后端应允许（即便会断开当前连接）

## 七、跨页联动

### 7.1 账号监控页（P13）同步
- 当会话被踢下线或拉黑后，「账号监控」页应收到事件更新
- 若使用全局事件总线，发送 `sb-sessions-update` 事件

### 7.2 风控哨兵页（P2）同步
- 若拉黑操作触发了风控规则，页面收到 `sb-sentinel-trigger` 事件
- 页面可选显示横幅提示

### 7.3 登录页（admin/static/login.html）
- 拉黑的 IP 在登录页会被 JS 检测并拒绝
- 提示文案：「该 IP 已被拉黑，无法登录。请联系管理员解除。」

## 八、实现要点

1. **实时同步**：操作后自动刷新列表，不依赖定时轮询
2. **乐观更新**：操作发送后立即更新 UI（若成功），失败时回滚
3. **确认对话框**：所有危险操作（revoke、ban、revoke-others）都需二次确认
4. **设备识别**：优先展示友好的设备名称，不显示完整 User-Agent
5. **性能优化**：
   - 仅在首次加载时获取完整数据
   - 操作后增量更新而非全量刷新
   - 拉黑列表可折叠（减少首屏内容）
6. **无障碍**：
   - 所有表格行用 `<tr>` 语义标签
   - 按钮使用 `role="button"` 或 `<button>` 元素
   - 时间戳提供 `aria-label`（完整文字描述）
   - 操作确认对话框用 `role="alertdialog"`
7. **国际化**：
   - 所有文案（「踢下线」「拉黑」等）提取到 i18n 配置
   - 时间格式根据地域调整
8. **主题适配**：
   - 颜色变量用 CSS Custom Properties
   - 表格行变灰时使用 `--fg-disabled`
   - 当前设备徽章用 `--c-ok`（绿色）

## 九、数据存储与缓存

### 本地缓存（可选）
- **sessionList**：最后一次获取的会话列表（TTL: 30 秒）
- **banList**：最后一次获取的拉黑列表（TTL: 30 秒）
- 用户手动刷新时绕过缓存

### 操作日志（后端）
- 所有踢下线、拉黑、解除拉黑操作需记录审计日志
- 包含：操作人 ID、操作类型、目标会话/IP、时间戳、原因（若有）
- 保留期：≥ 90 天
