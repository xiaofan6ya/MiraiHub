# 功能契约：平台网关（Gateway）

**页面标识**: P5（TABS 第五个）  
**入口函数**: `loadGateway()` / `loadGatewaySpeed()`  
**路由**: 侧栏「平台管理」→「网关配置」或 `/gateway`

## 二、数据来源与接口

### 主接口

#### 1. GET /api/gateway/config
**获取当前调度配置**

**返回字段**:
```json
{
  "strategy": "balance",                    // 当前策略 ID
  "strategies": [                            // 可用策略列表
    {
      "value": "priority",
      "label": "优先级策略",
      "description": "按平台配置的优先级顺序依次尝试"
    },
    {
      "value": "balance",
      "label": "平衡分摊",
      "description": "按平台账号数和健康度分摊流量"
    },
    // ... 其他策略（expiring, throughput, round_robin, random）
  ],
  "priority": {                              // 平台 -> 优先级数字
    "openai": 10,
    "deepseek": 20,
    "loomy": 30
  },
  "disabled": {                              // 平台 -> 禁用状态
    "openai": false,
    "deepseek": false
  },
  "spread_unbound": false,                   // 无头请求是否参与负载分摊
  "platforms": [                             // 平台元信息
    {
      "id": "openai",
      "label": "OpenAI",
      "managed": true
    },
    // ...
  ]
}
```

#### 2. PUT /api/gateway/config
**保存调度配置**

**请求体**（任选其一或组合）:
```json
{
  "strategy": "balance",                     // 策略 ID（可选）
  "priority": { "openai": 10, "deepseek": 20 },  // 优先级（可选）
  "disabled": { "openai": false },           // 平台禁用状态（可选）
  "spread_unbound": true                     // 是否分摊无头请求（可选）
}
```

**返回字段**:
```json
{
  "ok": true,
  "config": { /* 更新后的完整配置 */ }
}
```

#### 3. GET /api/gateway/order
**获取当前策略下的实际调度顺序**

**返回字段**:
```json
{
  "items": [
    {
      "platform": "openai",
      "label": "OpenAI",
      "rank": 1,                             // 在当前策略下的排序位置
      "reason": "优先级 10",                 // 排序原因说明
      "usable": 12,                          // 可用账号数
      "balance_remain": 456.78,              // 总可用额度
      "available": true                      // 是否有可用账号（false 时标灰）
    },
    // ... 其他平台
  ]
}
```

#### 4. GET /api/platform/speed
**获取平台性能对标数据**

**参数**:
- `hours`: 1-720（默认 24），数据窗口
- `model`: 可选，按模型过滤

**返回字段**:
```json
{
  "hours": 24,
  "model": "",                               // 过滤模型（若有）
  "items": [
    {
      "platform": "openai",
      "label": "OpenAI",
      "rank": 1,                             // 按 score 升序排名
      "requests": 1250,                      // 窗口内总请求数
      "ok_requests": 1210,                   // 成功请求数
      "success_rate": 96.8,                  // 成功率百分比
      
      "ttfb_p50": 320,                       // 首字响应时间中位数（毫秒）
      "ttfb_avg": 350,                       // 首字响应时间均值
      "latency_p50": 1240,                   // 总耗时中位数
      "latency_p95": 2150,                   // 总耗时 95 分位
      "jitter": 180,                         // 延迟标准差
      
      "tps_p50": 85.3,                       // 输出速度中位数（tokens/s）
      "tps_avg": 82.1,                       // 输出速度均值
      "samples": 1200,                       // 样本数
      "low_sample": false,                   // 是否样本不足（< 3）
      
      "score": 1.45                          // 综合评分（越低越好）
    },
    // ... 其他平台按 score 排序
  ],
  "fastest": "openai",                       // 最快平台 ID（样本 ≥ 3）
  "steadiest": "deepseek",                   // 最稳定平台 ID（jitter 最小）
  "observed_at": "2024-11-23T12:34:56Z"     // 数据采集时间戳
}
```

### 副接口

**禁用平台**:
```http
POST /api/gateway/disable
{
  "platform": "openai",
  "reason": "控制台手动操作"  // 可选
}
```

**启用平台**:
```http
POST /api/gateway/enable
{
  "platform": "openai",
  "reason": ""  // 可选
}
```

## 三、UI 组件与状态

### 3.1 策略选择器

**六个策略**（来自 /api/gateway/config 的 `strategies` 数组）:

| 策略 ID | 名称 | 说明 |
|--------|------|------|
| `priority` | 优先级策略 | 按配置的优先级数字顺序依次尝试（数字越小越先） |
| `balance` | 平衡分摊 | 按平台账号数与健康度计算权重，流量分摊 |
| `expiring` | 即将过期优先 | 优先用快要失效的 Key，避免浪费 |
| `throughput` | 吞吐量优先 | 选择 TPS 最高的平台 |
| `round_robin` | 轮询 | 请求轮流分配到各平台 |
| `random` | 随机 | 每次随机选一个可用平台 |

**按钮状态**:
- **当前策略**: `.active` 高亮（背景色 + 加粗）
- **非当前策略**: `.inactive` 灰显（可点击切换）

**交互**:
- 点击按钮 → `PUT /api/gateway/config { strategy: "xxx" }`
- 保存成功后：
  - 重新加载 `loadGateway()`
  - 触发 `gwOnStrategyChanged()` 更新拓扑动画

### 3.2 负载分摊开关

**说明文案**（根据状态动态显示）:

| 状态 | 文案 |
|------|------|
| OFF（默认）| 「无头请求走默认平台，调用必须指定 X-Platform 或 Key 要绑定平台」|
| ON | 「无头请求按策略分摊到各平台，支持多平台聚合（所有模型必须同名）」|

**交互**:
- 点击切换 → `PUT /api/gateway/config { spread_unbound: true/false }`
- Toast 提示：
  - ON: 「已开启：无头请求会按策略分摊到各平台」
  - OFF: 「已关闭：无头请求走默认平台」

### 3.3 拓扑动画

**使用库**: `window.WBTraffic.Topology`（HTML 容器: `#gwTraffic`）

**节点类型**:
- `key`: 调用方（左侧，图标 = 🔑 icon）
- `gateway`: 平台网关（中间，图标 = 🏛️ icon）
- `p-<platform>`: 各平台节点（右侧，图标 = 平台 logo）

**粒子流动画** (`fire` 方法):
- 参数: `fire(fromNodeId, toNodeId, { duration: 500 })`
- 粒子流方向: key → gateway → target platform
- 时序:
  - T=0: key → gateway (500ms)
  - T=460: gateway → platform (600ms)
  - 总耗时: ~1100ms

**策略切换时的更新** (`gwOnStrategyChanged`):
- **不重建节点**（避免 DOM 重排导致页面抽搐）
- **只更新**:
  - 各节点副标题: `${rank}. ${accounts} 个账号`
  - 高亮节点: 第一个平台加粗、加背景色
  - 活跃链接: gateway → 第一个平台
  - gateway 副标题: 「当前选：<平台名>」
- 演示粒子流: key → gateway → 第一个平台（单次）

**模拟 5 个请求** (`gwTrafficBurst`):
- 触发: 点击「模拟按钮」
- 粒子流方向: key → gateway → 各平台（轮流分配）
- 时序: 每 160ms 发出一条粒子流（总 5 条）
- 目标平台: 按当前策略顺序轮转
- gateway 副标题变化: 「本次 → <平台名>」（跟着粒子流更新）
- Toast: 「模拟 5 个请求，按当前策略分散到 N 个平台」

### 3.4 平台排序列表（可拖拽）

**每行内容**:
```
[拖拽柄] [logo] 平台名                    [第 1 位] [禁用/启用]
```

**拖拽排序**（FLIP 动画）:
1. 拖拽开始: 行加 `.dragging` 样式（变暗）
2. 拖拽中: 实时计算位移，其他行用 `transform: translateY(Δy)` 过渡
3. 拖拽结束:
   - 更新所有行的排名标签（「第 N 位」）
   - 重新编号: 第一行 = 10，第二行 = 20，以此类推
   - `PUT /api/gateway/config { priority: { openai: 10, deepseek: 20, ... } }`
   - Toast: 「调度顺序已保存」
   - 刷新右侧「当前调度顺序」（调用 `loadGatewayOrderOnly()`）

**禁用/启用按钮**:
- 按钮文字: 禁用 → 「禁用」、已禁用 → 「启用」
- 点击禁用:
  - 显示确认对话框: 「禁用后该平台不再参与调度…」
  - 若确认 → `POST /api/gateway/disable`
  - 成功 → 整页刷新 `loadGateway()`
  - 失败 → Toast 错误提示
- 点击启用:
  - 直接 `POST /api/gateway/enable`（不需确认）
  - 成功 → 整页刷新

**禁用状态样式**:
- 行加 `.disabled` 样式（变灰）
- 排名标签显示「已禁用」而非「第 N 位」
- 仍在列表中可见（便于重新启用）

### 3.5 性能对标卡

**时间粒度选择** (可选):
- 按钮组: 24h / 7d
- 点击刷新 → `GET /api/platform/speed?hours=24` 或 `hours=168`

**最快/最稳定平台卡**:
- 显示: 「最快：<平台名> TTFB 320ms · TPS 85.3 tok/s」
- 显示: 「最稳定：<平台名> Jitter 180ms」
- 若样本 < 3: 加 ⚠️ 标记与文案「样本不足，参考价值低」

**各平台排行表**:
- 按 `score` 升序排列（score 越低越好）
- 列: 排名 · 平台 · TTFB · TPS · 成功率 · 样本 · 评分

**数字格式化**（同 overview.md）:
- **TTFB/Latency**: 毫秒，不缩写，如 `320ms` / `1240ms`
- **TPS**: `tok/s` 单位，1 位小数，如 `85.3`
- **成功率**: 百分比 + % 号，如 `96.8%`
- **样本**: 整数，如 `1200`
- **评分**: `score` 是相对值，2 位小数，如 `1.45`（后端不承诺绝对数值）

**着色规则**:
- 绿色 ✓: TTFB ≤ 500ms **且** 成功率 ≥ 98%
- 黄色 ⚠: TTFB ≤ 1000ms **或** 成功率 ≥ 95%
- 红色 ✗: TTFB > 1000ms **或** 成功率 < 95%

**低样本警告**:
- 样本 < 3 时，行后缀「⚠️ 样本不足」
- 该平台不参与「最快」和「最稳定」评选（除非是唯一平台）

**悬停 Tooltip**（鼠标悬停表格行）:
```
OpenAI
账号数: 12 个
可用余额: ¥456.78
最早过期: 2024-12-15
```

**刷新时间戳**:
- 格式: 「最后更新 2024-11-23 12:34:56」（本地时间）
- 刷新按钮: 重新调用 `loadGatewaySpeed()`

## 四、交互与行为

### 4.1 页面加载

**首次进入**:
1. 显示加载状态（骨架屏或灰色占位符）
2. 并行调用:
   - `GET /api/gateway/config`
   - `GET /api/gateway/order`
3. 渲染左侧（策略、开关、说明）
4. 延迟 220ms 后初始化拓扑（`gwInitTraffic(true)`）
5. 渲染右侧（平台列表、当前顺序）
6. 后续异步调用 `loadGatewaySpeed()` 加载性能卡

**策略切换**:
1. 点击策略按钮 → 检查是否与当前策略相同
2. `PUT /api/gateway/config { strategy: "xxx" }`
3. Toast: 「策略已切换：<名称>」
4. 重新加载 `loadGateway()` 刷新全部
5. 触发 `gwOnStrategyChanged()` 更新拓扑动画

**负载分摊开关切换**:
1. 点击开关 → `PUT /api/gateway/config { spread_unbound: true/false }`
2. 成功 → Toast 提示，调用 `loadGatewayConfig()` 刷新配置显示
3. 失败 → Toast 错误提示

**平台拖拽排序**:
1. 鼠标 down: `dragstart` 事件，记录起始行 `dragRow`
2. 拖拽中: `dragover` 事件，实时计算位移并用 FLIP 过渡
3. 鼠标 up: `dragend` 事件，计算新顺序
4. `PUT /api/gateway/config { priority: { ... } }`
5. 成功 → Toast，刷新右侧「当前调度顺序」（`loadGatewayOrderOnly()`）
6. 失败 → 整页重新加载 `loadGateway()`

**禁用/启用平台**:
- **禁用**: 点击按钮 → 显示确认对话框 → 若确认 → `POST /api/gateway/disable` → `loadGateway()` 刷新全页
- **启用**: 点击按钮 → `POST /api/gateway/enable` → `loadGateway()` 刷新全页

**模拟按钮**:
1. 点击 → 检查拓扑是否已初始化（若未初始化则先初始化）
2. `const platforms = await gwTrafficPlatforms()`
3. 若无可用平台 → Toast 错误「没有可调度的平台」
4. 否则 → 触发 `gwTrafficBurst()` 执行动画
5. Toast: 「模拟 5 个请求，按当前策略分散到 N 个平台」

## 五、数据展示规范

### 5.1 数字格式化（同 overview.md）

| 场景 | 格式 | 示例 |
|------|------|------|
| TTFB/Latency | 毫秒，无缩写 | `320ms` / `1240ms` |
| TPS | 1 位小数 + `tok/s` | `85.3 tok/s` |
| 成功率 | 1 位小数 + `%` | `96.8%` |
| 账号数 | 整数 | `12 个` |
| 余额 | 千分位 + 2 位小数 + `¥` | `¥456.78` |

### 5.2 着色规则

| 指标 | 绿色 ✓ | 黄色 ⚠ | 红色 ✗ |
|------|--------|--------|--------|
| TTFB | ≤ 500ms | 500-1000ms | > 1000ms |
| 成功率 | ≥ 98% | 95-98% | < 95% |
| 综合 | ≤500ms && ≥98% | ≤1000ms \|\| ≥95% | >1000ms \|\| <95% |

### 5.3 文案

**策略说明卡** (示例):
```
当前策略：优先级策略

说明：按配置的优先级数字顺序依次尝试。
最先尝试的平台如果有可用账号且健康，就用它；
如果账号用完或不健康，才会尝试次优平台。

适用场景：单一主平台 + 备用平台（比如主要用 OpenAI，备用 Deepseek）

注意事项：
  · 优先级通过拖拽左下平台列表来调整
  · 不支持「某平台用完后自动补充」的流量贷功能
```

## 六、边界情况与容错

### 6.1 数据缺失或异常

| 情况 | 处理 |
|------|------|
| 无平台接入 | 显示「还没有接入平台」 |
| 全部平台被禁用 | 拓扑节点隐藏，显示「当前没有可用平台」 |
| 无可用账号 | 平台行变灰，显示「可用账号：0」 |
| 性能数据为空 | 卡片显示「暂无数据」或「数据更新中」 |
| 样本 < 3 | 加 ⚠️ 标记，标题加「样本不足」 |
| 拓扑初始化失败 | 模拟按钮 disabled，提示「拓扑加载失败」 |

### 6.2 加载态与错误

**加载中**:
- 显示骨架屏（表格行的灰色占位符）
- 卡片内容淡出（opacity: 0.6）

**请求失败**:
- 显示 Toast 错误: 「操作失败：<错误详情>」
- 页面保留上次数据（不清空）
- 提供「重试」按钮（重新加载该模块）

**响应超时** (> 5 秒):
- 显示降级视图（上次缓存数据）
- 后台继续重试
- 收到响应后自动更新

### 6.3 空状态

| 场景 | 显示 |
|------|------|
| 账户被禁用 | 顶部横幅「账户已禁用」，所有卡片置灰 |
| 无可用平台 | 显示「没有可用平台，请联系管理员」 |
| 新建平台（首次） | 拓扑显示 key + gateway，右侧平台节点为空，提示「暂无平台接入」 |

## 八、实现要点

1. **拓扑动画优化**:
   - 策略切换时**只更新高亮与文案，不重建节点** —— 避免 DOM 重排导致页面抽搐
   - 使用 `updateNodes()` 和 `setActiveLink()` 而非重新创建
   - 粒子流延迟精确到 ms（key→gateway 500ms, gateway→platform 600ms）

2. **拖拽排序**:
   - 使用 FLIP 动画而非直接 `position: absolute`
   - 计算前/后位移差，反向 transform，再过渡回 0
   - FLIP 完成后调用 `flip()` 只更新右侧「当前调度顺序」（避免重绘左侧列表）

3. **性能优化**:
   - 策略选择器用事件委托（单次绑定所有按钮）
   - 拓扑初始化延迟 220ms 后开始（让浏览器先布局其他元素）
   - 性能卡数据异步加载（不阻塞主要 UI）

4. **缓存策略**:
   - `/api/gateway/config` 缓存 30s，用户操作后清除
   - `/api/platform/speed` 缓存 5min（数据不实时）
   - 页面前置调用 `loadGateway()` 时绕过缓存

5. **错误处理**:
   - 所有 API 失败都显示 Toast，不中断用户操作
   - 拖拽保存失败时，整页重新加载（确保状态一致）
   - 平台禁用/启用失败时，重新加载 `loadGateway()` 恢复界面

6. **无障碍**:
   - 策略按钮用 `<button>` 且 `aria-label="策略名：说明"`
   - 拖拽手柄用 `aria-hidden="true"` + `data-tooltip` 文案
   - 数字用 `<span aria-label="完整数值描述">` 提供完整文字
   - 着色不单独依靠颜色，要有文字/图标补充

7. **国际化**:
   - 所有文案提取到 i18n（「优先级策略」「当前选」等）
   - 策略描述由后端返回（支持多语言）

8. **主题适应**:
   - 所有颜色用 CSS Custom Properties（`--success` / `--warning` / `--danger`）
   - 支持亮/暗主题无缝切换
