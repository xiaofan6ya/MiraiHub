# 功能契约：账号分析页（Account Analytics）

**页面标识**: P12（TABS 中「数据分析」或「账号分析」）  
**入口函数**: `loadAccountAnalytics()`  
**路由**: 侧栏「数据分析」菜单 或 概览页「账号监控」卡片点击「分析」

## 二、数据来源与接口

### 主接口

```http
GET /api/stats/accounts?
  days={1|7|30}&
  page={int}&
  per_page={10|25|50|100}&
  sort={field}:{asc|desc}&
  keyword={string}&
  platform={string}
```

**参数**:
- `days`: 时间窗口（1、7、30 天，对应「今日」「最近7天」「最近30天」）
- `page`: 页码（从 1 开始），默认 1
- `per_page`: 每页条数，默认 25
- `sort`: 排序字段与方向，如 `requests:desc`（请求数降序），默认 `-requests`
  - 可排序字段: `requests`, `success_rate`, `credits_consumed`, `avg_latency`, `created_at`
- `keyword`: 按账号名称、UID 子串搜索
- `platform`: 按平台过滤（来自 `X-Platform` 请求头，可选）

**返回字段**（`GET /api/stats/accounts`）:

```json
{
  "items": [
    {
      "account_id": 123,
      "account_name": "Account Name",
      "platform": "workbuddy",
      "uid": "user_12345",
      "status": "active",             // active | paused | disabled | no_balance
      "requests": 1250,               // 窗口内请求总数
      "ok_requests": 1245,            // 成功请求数
      "success_rate": 0.996,          // 成功率（0～1）
      "credits_consumed": 54.33,      // 消耗额度 / Token
      "avg_latency_ms": 320.5,        // 平均耗时（毫秒）
      "ttft_ms": 150.2,               // 首token耗时（部分平台）
      "tps": 42.3,                    // Token/秒吞吐（部分平台）
      "created_at": 1690000000        // 账号创建时间
    },
    // ... 更多账号
  ],
  "summary": {
    "total": 150,                      // 总账号数
    "total_requests": 187500,          // 窗口内总请求数
    "total_ok_requests": 186375,       // 总成功请求数
    "avg_success_rate": 0.994,         // 平均成功率
    "total_credits_consumed": 8150.5,  // 总消耗额度
    "avg_credits_consumed": 54.37,     // 平均每账号消耗
    "avg_latency_ms": 325.0,           // 平均耗时
    "accounts_active": 120,            // 活跃账号数
    "accounts_paused": 15,             // 暂停账号数
    "accounts_disabled": 10,           // 禁用账号数
    "accounts_no_balance": 5           // 无余额账号数
  },
  "paginated": true,                   // 是否分页
  "page": 1,
  "per_page": 25,
  "total_pages": 6
}
```

### 副接口

**获取账号详细分析（趋势数据）**:
```http
GET /api/stats/accounts/{account_id}?days={1|7|30}
```

**返回字段**:
```json
{
  "account_id": 123,
  "account_name": "Account Name",
  "platform": "workbuddy",
  "summary": {
    "requests": 1250,
    "ok_requests": 1245,
    "success_rate": 0.996,
    "credits_consumed": 54.33,
    "avg_latency_ms": 320.5
  },
  "trends": [
    {
      "time": 1700000000,              // Unix 时间戳，粒度为 1 天 / 1 周 / 1 小时（取决于 days）
      "requests": 100,
      "ok_requests": 99,
      "credits_consumed": 5.5,
      "avg_latency_ms": 315
    },
    // ... 更多时间点
  ]
}
```

### 参考接口（用于对标卡）

从 `/api/overview?days=X` 获取的 `summary` 中提取平均值，作为对标基准：
- 平均成功率: `overview.window.ok_requests / overview.window.requests`
- 平均消耗: `overview.window.credits`
- 平均耗时: 需后端补充或从 `/api/stats/accounts?days=X&sort=-requests` 的 `summary.avg_latency_ms`

## 三、数据展示规范

### 3.1 账号成功率着色

| 成功率范围 | 颜色 | 说明 |
|-----------|------|------|
| ≥ 98% | 🟢 绿 | `ok` 健康 |
| 90% ≤ < 98% | 🟡 黄 | `warn` 预警 |
| < 90% | 🔴 红 | `danger` 异常 |
| 无数据 / 已禁用 | 🔘 灰 | `disabled` |

### 3.2 数字格式化（复用 overview.md 规则）

#### 缩写格式（`ovNum()`）
- ≥ 1 亿（1e8）：`B`（亿），2 位小数，如 `1.23B`
- ≥ 1 万（1e4）：`M`（万），2 位小数，如 `12.34M`  
- ≥ 1 千（1e3）：`K`（千），1 位小数，如 `1.2K`
- < 1 千：显示原数，四舍五入

#### 千分位格式（`ovInt()`）
- 用于请求数、精确计数
- 规则：千分位分组，不缩写，如 `1,234,567`

#### 百分比格式（`fmtPercent(rate, decimals)`）
- 用于成功率
- 规则：乘以 100，固定指定小数位，如 `99.60%`

#### 金额格式（`fmtCredit(value, sign)`）
- 用于消耗、额度
- 规则：千分位 + 2 位小数，如 `1,234.56`

#### 时间格式（`fmtTime(s, withSec)` 或 `fmtLatency(ms)`）
- 耗时：毫秒 `ms`，如 `320.5ms` 或简化为 `321ms`
- 时间戳：`YYYY-MM-DD HH:mm:ss`

#### 对标卡增减格式（`fmtDelta(delta, pct)`）
- 增减百分点：`+5 pp` / `-3 pp`（百分点，用于成功率）
- 增减百分比：`+12%` / `-8%`（百分比，用于消耗、耗时）

### 3.3 表格列名动态调整（平台相关）

**WorkBuddy / CodeBuddy**:
- 列名：「账号」「请求数」「成功率」「消耗积分」「平均耗时」

**Trae**:
- 列名：「账号」「请求数」「成功率」「消耗 Token」「TTFT」

**Qoder / Loomy**:
- 列名：「账号」「请求数」「成功率」「消耗额度」「平均耗时」

## 四、交互与行为

### 4.1 页面加载

**首次进入**:
1. 显示加载状态（骨架屏）
2. 调用 `GET /api/stats/accounts?days=1&page=1&per_page=25&sort=-requests`
3. 渲染表格行、分页控制、汇总统计卡
4. 默认按请求数降序排列

**时间粒度切换** (1天 ↔ 7天 ↔ 30天):
1. 更新 URL 参数（可选）或本地状态
2. 重新调用接口，`days` 参数更新，重置到第 1 页
3. 表格平滑动画更新数值

**排序方式切换**（下拉菜单）:
1. 用户选择排序字段（请求数↓ / 成功率↓ / 消耗↓ / 速度↑）
2. 调用 `GET /api/stats/accounts?page=1&sort=field:desc`
3. 保留 `days` 参数和搜索条件

### 4.2 操作交互

#### 搜索与过滤
- 用户在搜索框输入关键字 → 防抖（300ms）
- 调用 `GET /api/stats/accounts?page=1&keyword=xxx`（重置到第 1 页）
- 表格平滑更新

#### 分页
- 点击前后按钮 或 选择页码
- 调用 `GET /api/stats/accounts?page=X&per_page=Y`
- 表格滚动到顶部（平滑）

#### 点击行进入详情抽屉
- 点击账号行 → 右侧展开抽屉
- 异步加载详细信息：调用 `GET /api/stats/accounts/{account_id}?days=X`
- 展示对标卡（vs 平均水平）和趋势图表

#### 对标卡展示
- 对比当前账号与全平台平均：
  - 请求数、成功率、消耗、耗时
  - 每项显示差值和百分比变化
  - 超过平均值绿色标记「↑」，低于平均黄色「↓」

#### 趋势图表
- 请求趋势：折线图显示总请求 vs 成功请求
- 消耗趋势：柱状图显示每日消耗
- 时间粒度：1天显示按小时、7天按天、30天按周
- 图表支持悬停查看精确数值（Tooltip）
- 支持图例点击隐藏/显示数据线

#### 平台切换
- 通过平台上下文事件 `wb-platform-change` 触发
- 自动刷新表格（调用 `loadAccountAnalytics()`）
- 保留当前时间粒度和排序条件

### 4.3 刷新按钮
- 位置：页面右上角
- 行为：重新加载账号分析数据（保留当前条件）
- 显示：最后刷新时间戳

## 五、跨页联动

### 5.1 平台上下文
- 所有 API 请求自动按 `X-Platform` 请求头过滤
- 切平台时 localStorage 同步，页面自动刷新

### 5.2 导航跳转
- 点击账号行 → 在侧抽屉显示详情（本页内）
- 侧抽屉中「查看使用记录」→ 跳转到「日志」页（P7），按此账号过滤
- 侧抽屉中「管理账号」→ 跳转到「账号管理」页（P13），定位该账号
- 点击汇总统计的某个数值 → 可选：跳转到相关页面或展开详情

### 5.3 全局事件
- 账号状态变化后，全局事件 `wb-account-updated` 广播
- 此页若处于前台，重新加载表格
- 若目标账号的状态变为 disabled，抽屉自动刷新并显示灰色

## 六、边界情况与容错

### 6.1 数据缺失或异常

| 情况 | 处理 |
|------|------|
| 账号名称缺失 | 显示 `—` 或 UID（若有） |
| 请求数为 0 | 显示 `0`，不着色 |
| 成功率无法计算（分母为 0） | 显示 `—` |
| 消耗为 0 | 显示 `0.00` |
| 耗时无数据 | 显示 `—` |
| 趋势数据为空 | 在图表区显示「暂无数据」 |
| 平台标签缺失 | 显示平台代码 |

### 6.2 加载态与错误

**加载中**:
- 表格显示骨架屏（整行灰色占位符）
- 保留上次成功的数据
- 侧抽屉加载趋势数据时显示 Loading Spinner

**请求失败**:
- 显示 Toast 错误提示：「数据加载失败，请重试」
- 保留上次成功的数据（若有）
- 提供「重试」按钮

**响应超时**（> 10 秒）:
- 显示降级视图（上次缓存数据 或 只显示时间戳）
- 后台继续重试

### 6.3 空状态

| 场景 | 显示 |
|------|------|
| 无账号数据 | 表格显示「暂无账号数据」 |
| 搜索无结果 | 表格显示「没有匹配的账号，试试调整搜索条件」 |
| 账号池被禁用 | 顶部横幅「此平台的账号池已禁用，请联系管理员」 |
| 权限不足 | 显示「您没有权限访问此页面」 |
| 账号被禁用 | 侧抽屉中该行整体置灰，状态标记为「已禁用」 |

### 6.4 冲突与竞态

**账号被并发删除**:
- 页面尝试加载趋势数据时返回 404
- Toast 提示「账号已被删除」
- 自动从列表中移除该行或关闭侧抽屉

**账号状态变化**:
- 若目标账号从 active 变为 disabled，侧抽屉自动刷新
- 表格中该行状态徽章更新

### 6.5 功能开关与平台差异

**平台只读字段**:
- 某些平台可能不提供 `ttft_ms` 或 `tps` 字段
- 表格列动态隐藏不支持的字段

**端差异**（PC vs 移动）:
- **PC**: 表格横向排列，侧抽屉固定右侧，图表并排显示
- **移动**: 表格响应式缩列，侧抽屉全屏或从下方 slide up，图表纵向堆叠

## 八、实现要点

1. **缓存策略**：账号分析列表缓存 30 秒，用户点击刷新时 `force=true` 绕过缓存；趋势数据缓存 1 分钟

2. **性能优化**：
   - 大量账号时用虚拟滚动（Virtual Scroll）避免 DOM 爆炸
   - 搜索/排序 300ms 防抖
   - 分页服务端分页，单页不超过 100 条
   - 侧抽屉详情数据延迟加载，避免全页加载阻塞
   - 趋势图表按需渲染（侧抽屉展开时）

3. **无障碍**:
   - 表格用 `<table>` 语义标签，行用 `<tr>`，单元格用 `<td>`
   - 成功率徽章用 `aria-label` 提供完整文字描述，不单依赖颜色
   - 操作按钮用 `<button>` 且有 `aria-label`
   - 搜索框有 `<label>`，关联 `for` 和 `id`
   - 图表用 `<figure>` + `<figcaption>` 包裹

4. **国际化**：所有文案（「账号分析」「请求数」「成功率」等）提取到 i18n 配置

5. **主题适应**：所有颜色变量用 CSS Custom Properties（`--ok`、`--warn`、`--danger` 等），支持亮/暗主题切换

6. **实时刷新**（可选高级功能）:
   - 通过 SSE 或 WebSocket 实时推送账号统计数据
   - 页面自动更新行的指标，无需手动刷新

7. **数据精度**:
   - 成功率用 `0～1` 的小数存储，前端乘以 100 显示为百分比
   - 耗时用毫秒整数或一位小数存储
   - 金额用分或最小单位存储，前端除以 100 显示为元/积分

8. **排序多字段**:
   - 若后端支持，可支持「按成功率降序，再按请求数降序」等多字段排序
   - 目前仅支持单字段排序
